# Producto — índice y guía de contexto

## Cuándo usar esta sección

Lee esta sección para decidir alcance, público, propuesta de valor, criterios de éxito o exclusiones. No la uses para elegir librerías ni definir contratos técnicos.

## Orden de lectura

1. [Product Brief aprobado](../../../docs/superpowers/specs/2026-09-27-metro-app-product-brief-design.md).
2. [Reglas del experimento comunitario](../community/experiment-rules.md) si la decisión afecta participación o aprendizaje.
3. [Arquitectura vigente](../architecture/system-map.md) solo si la decisión cambia límites del sistema.

## Skills relacionados

- `superpowers:brainstorming`: cambios de alcance, experiencia o comportamiento todavía no diseñados.
- `architecture-workflow`: cambios que alteran componentes, integraciones, datos o fuentes de verdad.
- `superpowers:writing-plans`: únicamente después de aprobar la especificación escrita.

## Fuente de verdad

El Product Brief enlazado arriba es la fuente de verdad del alcance del MVP. Si una decisión de arquitectura exige cambiar el producto, actualiza primero ese brief y solicita aprobación.
