# Arquitectura — índice y guía de contexto

## Cuándo usar esta sección

Lee esta sección para límites entre sistemas, contratos, integraciones, seguridad, identidad, persistencia, despliegue o cambios de fuente de verdad.

## Orden de lectura

1. [`system-map.md`](system-map.md) para el estado consolidado.
2. [ADRs aceptados](../../adr/INDEX.md) para la razón y condiciones de reapertura.
3. [Intake de la iniciativa](../../runs/2026-09-27-metro-app-v1/architecture-intake.yaml) para requisitos y preguntas abiertas.
4. La sección propietaria del cambio: [juego](../game/INDEX.md), [comunidad](../community/INDEX.md) u [operaciones](../operations/INDEX.md).

## Skills relacionados

- `architecture-workflow`: arquitectura, opciones, riesgos, ADRs y backlog.
- `superpowers:brainstorming`: requisitos o comportamiento todavía ambiguos.
- `superpowers:writing-plans`: plan de implementación después de aprobar la arquitectura escrita.

## Reglas de actualización

Una decisión arquitectural aceptada requiere actualizar `system-map.md`, su ADR y el índice afectado. No conviertas una integración propuesta en dependencia hasta que se apruebe explícitamente.
